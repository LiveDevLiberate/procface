# Design

## Context

当前 daemon 已有 health、内存窗口、慢客户端关闭和 compact SSE，但缺少统一的采样耗时与发布字节统计。PC/WSL 基线可作为比较基线，嵌入式设备仍需要在不增加持久化和运行时依赖的前提下测量真实成本。

## Goals / Non-Goals

**Goals:**

- 使用单调时钟记录采样轮次和 Trace 轮次耗时。
- 在发布边界统计编码后的字节数、批次数和慢客户端结果。
- 保持现有 v1 API、样本 schema、60 秒窗口和单客户端默认限制。
- 提供可重复的 PC/WSL 测量脚本和长时间运行验收数据。

**Non-Goals:**

- 本 change 不切换 SSE 为 WebSocket。
- 本 change 不改变默认采样间隔或增加设备端持久化。
- 本 change 不做跨架构最终兼容性承诺。

## Decisions

- 统计放在 daemon 发布层而不是前端推断，因为前端无法可靠区分编码、网络和浏览器处理成本。
- health 只返回累计计数与最近窗口值，不保存逐请求日志，避免内存膨胀。
- 默认保持响应字段向后兼容；新增字段使用可选 JSON 字段，TSV 样本列不变。
- 性能脚本分别测无客户端、SSE、SSE+Trace、慢客户端和 300/3000 进程，记录 CPU、RSS、窗口字节、发布字节和超时。

## Risks / Trade-offs

- [Risk] 统计字段自身增加少量锁竞争 → 使用原子计数和采样边界快照，避免每个样本单独加锁。
- [Risk] WSL 结果不能代表嵌入式设备 → 把结果标注为 PC 基线，并保留目标板复测入口。
- [Risk] 新 health 字段被旧前端忽略 → 只增加可选字段，不修改现有字段语义。

## Migration Plan

先实现只读统计和测量脚本，确认开销后再决定是否启用更紧凑的传输选项。回滚时删除新增统计字段即可，不影响历史样本解码。
