# Design

## Context

ProcFace 前端已经是无外部依赖的单体 HTML，拥有指标图表、历史、SSE 和 Trace 视图。后端只发布规范化指标，不应承担 Linux 组件的视觉分层或拓扑关系；本 change 只扩展前端展示层。

## Goals / Non-Goals

**Goals:**

- 用 profiler 风格的数据流图表达 Linux 子系统的组件和性能接口。
- 让节点和连线复用现有 metric ID、entity、单位、状态和历史数据。
- 保持单体 HTML、离线可打开、无新增依赖和现有连接生命周期不变。

**Non-Goals:**

- 不实现通用拓扑编辑器、dashboard builder 或用户自定义连线。
- 不让 daemon 返回架构图、节点定义或接口关系。
- 不推断 procfs 未提供的内核内部调用关系；静态图中的关系只表示可观测性能路径。
- 不在首版加入自动瓶颈诊断或告警规则。

## Decisions

- **图形技术**：使用原生 SVG，节点和连线是 HTML 内嵌的静态元素；避免图形库体积、初始化成本和离线依赖。
- **图定义**：前端维护按子系统分组的静态对象，包含节点、连线、布局、标签和 metric 绑定。数据到达后只更新值、状态和颜色。
- **首批图**：先提供 Scheduler、Memory、VFS/Filesystem、Block I/O、Networking、IRQ/SoftIRQ、Process 七个入口；指标不足时仍显示结构和状态占位。
- **数据绑定**：节点/连线绑定稳定 metric ID 和可选 entity 过滤器。一个图形元素可绑定多个指标，但必须定义主摘要指标和详情列表。
- **状态表达**：颜色表达活动/异常等级，文字同时表达状态名和原因；断链、历史 gap 和 complete 状态沿用现有图表语义。
- **交互**：点击节点或连线打开现有指标图表面板；使用原生 SVG viewBox 缩放或简化缩放控制，不引入画布框架。

## Risks / Trade-offs

- [procfs 只能外部观测部分路径] → 图定义标注观测指标，数据不足显示 unsupported，不声称完整内核调用图。
- [不同设备指标可用性不同] → 结构保留、数据按 capabilities/status 降级；不隐藏整个子系统造成布局跳变。
- [SVG 节点增多影响可读性] → 每个子系统独立图，首版限制节点和连线数量，详情放到既有图表。
- [颜色在串口/色盲环境不可见] → 所有状态同时显示文字、图例和 aria-label。
