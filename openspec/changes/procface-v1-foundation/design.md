# Design

## Context

项目目前只有规格与调研文档，没有 Rust 实现。动机见 proposal.md。本次沿用四个能力目录，不新增重复的 v1 指标或前端能力。主规格与旧 change 存在历史表述差异，本 change 采用最近确认的轻量全扫描、独立 trace 和独立 HTML 方案。

## Goals / Non-Goals

**Goals:**
- 采集、网络发布、trace 和 SQLite 之间通过有界队列和不可变快照隔离。
- 在同一规范化模型上实现 CLI、API、前端和 Prometheus，统一处理缺失值与生命周期。

**Non-Goals:**
- 不实现亚秒采样、任意 procfs 写入、远程命令、通用数据库查询或设备端网页托管。
- 不复制 sysstat 代码；MIT 产物独立实现。

## Decisions

### 构建与命令

所有构建的命令仍为 `procface`，不新增 diagnostic 子命令。Cargo 默认特性不含 SQLite；diagnostic 特性组合包含 SQLite 和敏感读取器，构建时仍使用 release 优化。发布包用文件名区分普通与诊断版本，包内二进制同名。能力接口区分已编译能力与运行时启用状态。

CLI 的 sample、trace、capabilities 与 daemon 直接复用同一 procfs 解析和采集核心；CLI 不以 HTTP 导出作为本地采样入口，不要求 daemon 运行。

### 线程与数据发布

主采样线程负责系统指标和普通进程轻量采集，系统数据完成后立即发布，不等待进程扫描。单独 trace worker 执行深度读取。HTTP 事件循环处理序列化和网络 I/O，SQLite worker 独立写入。每类数据保留原始采样时间与序列，不能给旧进程数据贴新时间。共享快照只短时加锁，不在锁内进行 I/O。

所有周期至少 1 秒，不重叠启动同一类采集。普通进程和 trace 默认各有 500 ms 合作式预算；预算检查发生在文件读取之间。已经阻塞的内核读取无法保证在预算点强制中断，停止状态可暂为 stopping，期间禁止创建替代 worker。

### 进程与资源

枚举 PID 后检查所有者，只读取授权范围内进程的详细数据，默认范围为当前用户。普通采集仅 stat/status；不能把普通列表 I/O 缺失伪造为零。取消旧的 256 进程结果限制；在资源预算内完成的一轮提供全部轻量记录，后端不按指标排序或截断排名结果。前端排序、筛选并默认展示前 16 个，可查看剩余进程。维护 PID 与 starttime 基线后计算 CPU，基线仍有 O(N) 内存成本；退出实体及时淘汰。超时跳过本轮，内存预算不足时报告覆盖不全，不得将旧数据或部分数据伪装为完整新一轮。trace 数据单独缓存，切换页面不停止普通订阅。

普通缓存、trace 缓存和发送队列均有界。具体字节上限、默认值及淘汰策略通过实现后测量确定并优化；测量覆盖基础内存、不同进程数量、trace 与慢客户端积压。此项是实现验证任务，不再预先冻结未经实测的数值。

### 流与历史

API 机器可读数据统一采用紧凑 JSON 数组，不让 HTTP current/series/stream/export 各自定义格式。批次使用 `[sequence, uptime, timestamp_unix, group_id, samples]`，样本使用 `[metric_id, entity_id, value, status_id]`；目录只在 capabilities 或 session 变更时传送。CLI 是人类入口，直接输出带字段名的展开 JSON/JSONL/TSV/table，不要求用户理解 API 数组位置。后续可在相同 API 数据模型上增加 CBOR/MessagePack，不改变语义。

trace 生命周期属于 daemon，不绑定浏览器连接。前端重连后查询当前 trace，展示 PID、进程身份与状态，并提供停止与切换操作。切换先停止旧 trace，等待 worker 退出后再启动新目标；stopping 期间仍保持单活动 trace 约束，启动返回 409。普通采集与已有历史不受影响。

客户端发送队列达到积压上限时断开该慢客户端并释放队列，不阻塞采样线程或 trace worker。重连仅补偿内存窗口内的数据；窗口外缺口由前端明确标记，不做插值。

当前快照、60 秒短窗口和客户端队列均有字节上限，不能仅以时间限制内存。SSE 使用 fetch 携带 Authorization；心跳 15 秒。前端先补历史再建立实时流后，按连接序列检查切换期间缺口，再做一次有界 series 查询并去重；窗口以外的数据明确标记丢失。SQLite 不扩大 series 的内存查询范围。

### 静态网页与跨域

单文件 HTML 的界面、样式和运行逻辑不加载外部资源，在 GitHub Pages 固定入口部署，同时保留 Release 版本下载。两个入口使用相同的正式 HTML 字节，部署不得再次改写产物。在线页面加载后浏览器直接连接用户填写的 daemon，GitHub Pages 不中转设备数据或 token。

跨域默认拒绝，用户显式配置在线站点的完整 Origin；项目路径不是 Origin 的一部分。本地文件模式以单独显式开关允许 null origin，不能将其识别成某个可信文件，仍验证 token。此配置不关闭浏览器安全机制。页面提供本地网络权限和混合内容等连接失败的排查提示，无法直接连接时提供开发机静态 HTTP 托管方式。IndexedDB 不可用时明确提示历史无法持久保存。预检只返回协议信息，不返回设备数据。

### 前端布局与视觉

采用总览、进程、Trace 三个标签页；连接状态栏和历史/导出工具栏共用。连接成功后配置折叠，仍可主动展开。总览按 CPU、负载、内存、磁盘和网络组织图表，更多指标按需展开；进程页保留 top 风格表格，Trace 页放控制、曲线和可折叠详情。标签页仅控制可见视图，不控制采集、订阅和历史保存生命周期。

视觉贴近 ASCII 终端：等宽字体、黑白灰、细边框、无圆角阴影、方括号文本按钮；图表仍用细线曲线与坐标。颜色只辅助区分，不替代文字。保持数值列宽与右对齐，复用显示节点以避免刷新空白、布局跳动和详情折叠。本轮仅冻结布局，界面实现和优化安排在后续阶段，见 tasks 7.10。

### SQLite

诊断构建包含能力但不默认写入。启用路径由启动参数给出，默认上限 16 MiB、保留 1 小时、30 秒 flush，默认不使用 WAL。按最旧样本淘汰并复用空闲页；DELETE 不保证文件缩小，需页数限制及事务空间预算。持久化错误停止写入并报告，不删除损坏文件，不影响实时接口。

保留期使用持久化的运行时长时钟，结合 procfs boot_id 区分启动周期。同一 boot_id 下，daemon 重启之间的 uptime 增量计入年龄；设备重启或 boot_id 不可用时，不推测未知断电时间，旧数据随后续可确认的运行时长继续老化。RTC 不参与淘汰。容量上限独立生效。早期开发数据库升级时给无法恢复年龄的记录建立保守基线。

### 前端完整性与建链边界

发布分两步：先签署前端版本、构建 ID 与 API 兼容范围组成的版本声明并内嵌 HTML；再对最终 HTML 原始字节计算 SHA-256，生成绑定文件名、摘要和同一版本信息的外部签名校验清单。内嵌声明不包含最终 HTML 摘要，避免自引用；外部清单用于执行页面前的独立文件校验。校验依赖预先信任的发布公钥，同一下载来源提供的任意公钥不能自动成为信任根。签名私钥仅用于发布流程。

前端建链提交版本、构建 ID 和内嵌的签名版本声明；daemon 本地验证签名和字段一致性，接受受信任发布密钥签署且 API 范围兼容的正式版本，不要求与 daemon 软件版本完全一致。设备和离线前端都不依赖联网查询 GitHub。声明是公开发布元数据，修改版仍可能复用官方声明，因此检查不构成远程运行完整性证明，也不证明当前页面已完成外部文件校验。

开发调试开关默认关闭，仅允许显式接入未签名的本地开发前端；签名错误不能自动降级为未签名模式。调试仍要求 token、允许的来源与 API 兼容，在 stderr、能力响应和页面中显示。该开关与 diagnostic 构建独立，不开启敏感诊断或持久化。

本期不引入浏览器远程证明或原生受信任启动器。原有脚本导出和 Prometheus 客户端继续使用其鉴权协议，不要求伪装为 HTML 前端；前端发布信息不作为授权凭据。签名编码、公钥轮换和错误码由实施设计选定并测试。

### 前端建链接口流程

1. 用户填写 daemon 地址和 token；浏览器按来源完成必要预检，daemon 仅对显式允许的来源返回许可。
2. 前端携带 Bearer token 读取 capabilities，检查 API 范围与开发调试状态；不兼容时停止并显示推荐前端版本。
3. 前端通过 `POST /api/v1/frontend/handshake` 提交版本、构建 ID、API 范围及签名版本声明；未签名开发前端显式标记开发模式且不提供签名。
4. daemon 校验 token、来源规则、发布声明或已启用的开发调试策略以及 API 兼容性，返回接受结果或结构化拒绝原因。握手不签发新的权限凭据，各数据请求仍使用 Bearer token。
5. 接受后前端查询当前 trace 状态，补齐内存窗口内的历史并订阅 SSE，按序列检查缺口与去重。重新建链重复版本检查；失败不停止 daemon 普通采集或当前 trace。

### 版本与状态

紧凑协议继续使用 API v1，不引入 v2 路径。旧预览 Release 撤下，保留 Git 标签与提交历史作为追溯；本次不保留旧线格式兼容分支。API 主版本不再单独证明线格式兼容，建链须同时检查紧凑 schema 标识，旧客户端、旧 daemon 和既有历史按各自版本明确处理。删除 Release 不会更新已部署的 Pages；待新协议和匹配前端完成后重新签名、发布并部署。

软件、HTTP API、样本 schema 分别版本化。首版通过 v1 capabilities 握手，不可用或范围不匹配即拒绝数据连接。sample.status 与任务状态分离：timed_out/degraded 是任务状态，沿用旧值时 sample.status 为 stale。Prometheus 将 rate 映射为 gauge，counter 映射为 counter，不直接暴露未知类型。

## Risks / Trade-offs

- [历史规格存在冲突] → 实施前以本 change 的明确修订为准，未决语义不能靠测试通过掩盖；同步时逐条核对。
- [目标板尚未提供] → 交叉编译、模拟运行和实际设备验证分别报告，不把编译成功视为 Linux 4.19 运行保证。
- [trace 单次读取可能耗时] → 隔离 worker、文件字节上限与合作式停止，不声称线程能硬中断任意内核调用。
- [大进程数与慢网络] → 内存字节上限、丢弃整轮不完整结果、断开慢客户端并显式标记缺口。

## Migration Plan

按 tasks 分阶段实现并验证；本次仅提交规划。三个旧 change 保留为历史参考，不单独 apply，也不标记为已实现。完成后同步主规格并归档本 change，旧草案另行标记被替代。
